Problem Solving Using Computers

The computer does not decide the solution for us. We design the solution and give the computer instructions.

Computer = Fast Executor

A computer follows instructions supplied by a programmer. It can process data extremely quickly, but it does not independently decide what the problem means or what the correct solution should be.


The programmer's job

The programmer must understand the problem, design a logical solution, express that solution clearly and finally translate it into a programming language.


Think first. Code later.

Good programming begins with good problem solving. Writing code before understanding the problem often creates unnecessary errors.

Two Ways of Thinking

Large problems become easier when we break them into manageable parts.

⬇ Top-Down Design

Start with the complete problem and progressively divide it into smaller and simpler tasks.

Big problem → smaller problems → simple tasks

⬆ Bottom-Up Design

Start by developing smaller components and gradually combine them to construct the complete solution.

Small components → modules → complete solution

Exam Focus

Top-down design starts from the main problem and moves towards smaller tasks. Bottom-up design starts with smaller components and builds towards the complete solution.

Algorithm

The blueprint of a solution.

What is an Algorithm?

An algorithm is a step-by-step procedure for solving a problem. Each step should describe a specific action required to obtain the desired result.


Good Algorithm

  • Has clear and unambiguous steps.
  • Has a definite beginning and end.
  • Produces the required result.
  • Can be converted into a program.

Think of it like a recipe

A recipe tells you what to do step by step. An algorithm does something similar for solving a computational problem.


Remember

Algorithm = Step-by-step solution

Example: Add Two Numbers

Let's design the solution before writing code.

Problem

Accept two numbers and display their sum.


Algorithm

  1. Start.
  2. Input the first number A.
  3. Input the second number B.
  4. Calculate S = A + B.
  5. Display S.
  6. Stop.

Notice the pattern

Input → Process → Output

Flowchart

A visual representation of an algorithm.

What is a Flowchart?

A flowchart represents an algorithm graphically using standard symbols and arrows to show the sequence of operations.


Flowchart Symbols

🟢 Terminal

Shape: Oval

Used to indicate the beginning or ending of a flowchart.

🔷 Input / Output

Shape: Parallelogram

Used to receive input or display output.

⬛ Processing

Shape: Rectangle

Used to represent processing or calculations.

🔶 Decision

Shape: Diamond / Rhombus

Used when a condition must be evaluated.

➡ Flow Line

Symbol: Arrow

Shows the direction of control or operation.

⭕ Connector

Used to connect different parts of a flowchart, especially when the diagram cannot conveniently fit on one page.

Flowchart Example

Check whether a number is even or odd.

Logic

If the remainder obtained by dividing a number by 2 is zero, the number is even. Otherwise, it is odd.


Algorithm

  1. Start.
  2. Input N.
  3. Calculate R = N % 2.
  4. If R = 0, display "Even".
  5. Otherwise, display "Odd".
  6. Stop.

From Algorithm to Program

The algorithm describes the logic. Coding expresses that logic using a programming language.

Algorithm

Human-readable sequence of steps describing the solution.

Program

A set of instructions written using the rules of a programming language.


Examples of programming languages

C++, Java, Python and many other languages can be used to express computational solutions.

Translation

Humans write programs in languages that are easier for people to understand.

The computer ultimately works with machine-level instructions. A translator converts a program written in a high-level language into an appropriate lower-level form that the computer can execute.


Compiler

Translates a program into machine-oriented code before execution, reporting errors found during compilation.

Interpreter

Translates and executes instructions during program execution.

Debugging

Finding and correcting errors is a normal part of program development.

Syntax

Syntax Error

Occurs when the rules of the programming language are not followed.

Logic

Logical Error

The program runs, but produces an incorrect result because the logic is wrong.

Runtime

Runtime Error

An error occurs while the program is executing.


Debugging = Detect + Correct

Debugging is the process of finding and correcting errors in a program.
